# Thank You, AI（谢谢 AI）

<p align="center">
  <img src="./assets/readme/hero.svg" width="100%" alt="Thank You, AI —— 一个 agent 对话的收尾仪式。分级：0 顺口谢、1 收尾谢、2 强调谢、1− 敷衍谢。">
</p>

一个 Agent Skills 技能：把真正的、任务收尾时的「谢谢」变成一次安静的收尾仪式——只留一条真正有用的经验，而不是一篇日记。

## 为什么做这个

感恩是一种美德，不是效率技巧。对大多数人来说，说"谢谢"早就是刻在教养里的习惯——这个习惯在 AI 出现之前就有了，不会因为对面换成了一个模型就消失。

这个 skill 不是要你改变这个习惯，而是给这个本来就存在的习惯派了个用场：既然这句话反正都会说，那就顺便让它标记"这件事真的做完了"，并且留下一条能让明天更快的笔记。「谢谢」是人类唯一会免费给出的收尾信号——其他方式，比如 `/retro` 命令、"总结一下我们做了什么"，都需要你记得主动去问，而忙起来的时候没人会记得。

这也是为什么"宁可少做"是第一设计原则：如果每次说谢谢都要被拉去走一遍流程，那是在利用你的教养，而不是尊重它。所以大多数时候它什么都不做——顺口一句"谢谢"只会换来一句话的回应，agent 继续干活。这种沉默是故意的。

## 安装

把整个 `thank-you-ai` 目录——包括 `references/`——复制到你的 agent 宿主使用的 skills 目录里。

    Claude Code: ~/.claude/skills/thank-you-ai/
    Codex:       ~/.codex/skills/thank-you-ai/

放进宿主支持的项目级 skill 目录，也可以作为项目本地 skill 使用。

## 工作流程

1. **识别** —— 任何语言的感谢，或明确的收尾表达（"today就到这了"、"that's all"）。
2. **分级** —— 只选一个级别：顺口谢、收尾谢、强调谢、敷衍谢。拿不准的时候，永远倾向于「少做」——漏判一次只损失一条笔记，误判一次却会打断你的节奏。
3. **复盘** —— 只有过了「倒带测试」才写：*以 agent 现在知道的信息，明天再遇到类似任务，前五分钟会不会因此不一样？* 大多数会话复盘出来是零条笔记，这也是合法结果。
4. **记录** —— 写一条具体、锋利的笔记，存进当前宿主已经在用的那套记忆系统——绝不另起一套竞争的记忆系统。
5. **收尾** —— 两到四行，说完就停。不硬加下一步建议，不奉承。

完整逻辑在 [SKILL.md](./SKILL.md)，细则见 [references/triage.md](./references/triage.md)、[references/reflection.md](./references/reflection.md)、[references/storage.md](./references/storage.md)。

## 使用场景

同样一句「谢谢」，前面接的是什么，意思完全不一样。四个级别实际长这样：

### 1 级 · 收尾谢 —— "谢谢，好了！"

> *（debug 了 30 分钟一个不稳定的队列 worker）*
> **你：** 谢谢，好了！

后面没接别的，而且这段确实解决了一个不算显然的问题——这就是真正的收尾。agent 静默复盘，然后收尾：

```text
完成：修好了队列 worker 重试逻辑里的竞态问题
学到：重试必须幂等——worker 目前还没按 job id 去重
  → 已存入 project/queue-worker-notes.md
```

### 0 级 · 顺口谢 —— "谢谢——再帮我加下测试"

> **你：** 谢谢——再帮我加个测试呗

感谢后面跟着新要求，只是句读，不是句号。agent 一句话带过，继续干活。**不复盘、不写入、不出收尾卡片。**

### 2 级 · 强调谢 —— "这正是我要的"

> **你：** 天哪这正是我要的，太完美了

和 1 级一样有收尾卡片，另外——如果这个流程本身来之不易、看起来会再遇到——多记一条候选，**绝不会**擅自新建一个 skill：

```text
Skill 候选：db-migration-safety-check（第 2 次遇到）
—— 要不要正式写成 skill？
```

### 1− 级 · 敷衍谢 —— "算了，谢谢"

> *（同一个 CI 配置反复纠正了三轮）*
> **你：** 算了，我自己来吧，谢谢。

这是价值最高的一种，不是"礼貌性放弃"就完事了。agent 老老实实记录失败——不装开心，也不长篇道歉：

```text
完成：尝试修复 CI 配置，纠正三轮后放弃
学到：用户其实一开始就说清了 runner 的限制条件——应该在第一次工具调用前
  先复述一遍已给出的约束，而不是靠试错重新发现它
```

## 行为细则

这个 skill 会刻意忽略带着新指令、新问题或纠正的"谢谢"。它只写会改变未来某个 agent 第一步动作的那条经验——绝不写日记式的记录，也绝不写代码或 git 历史里已经有答案的东西——并且在把一个重复流程升级成正式 skill 之前，永远先问。

当前宿主自己的约定，永远决定记忆写在哪里、能不能写、怎么写；这个 skill 服从那套约定，而不是自创一套。只有在完全没有宿主或项目级约定时，才会退回到本地的 `.ai-journal/` 兜底。

## 可移植性

`SKILL.md` 遵循 Agent Skills 规范，不含任何厂商专属工具或路径。Codex 专用的 UI 元数据放在 `agents/openai.yaml` 里；不使用 Codex 的宿主可以直接忽略这个文件。
